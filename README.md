# Видеонаблюдение Amatek — собственное веб-приложение

Веб-приложение для просмотра IP-камер и регистраторов **Amatek** (RTSP) прямо в браузере,
без установки клиентов и без китайских облачных сервисов.

Сервер стоит **в вашей локальной сети** рядом с регистраторами/камерами, забирает RTSP-потоки
и раздаёт их браузеру как HLS. Архив остаётся на регистраторе — ПО его не заменяет, а даёт
удобный и быстрый «живой» просмотр с любого устройства в сети.

```
IP-камера / NVR Amatek ──RTSP──> сервер приложения (ffmpeg) ──HLS──> браузер (hls.js)
```

---

## Что уже умеет

| Возможность | Детали |
|---|---|
| **Живой просмотр** | Сетки 1×1, 2×2, 3×3, 4×4, выбор потока на плитку, полноэкранный режим, двойной клик — развернуть камеру |
| **Основной / дополнительный поток** | Кнопка `sub`/`main` на плитке: в сетке 16 камер удобно смотреть «дополнительный» поток, в полноэкранном — основной |
| **Группы и поиск** | Камеры группируются (Периметр, Вход…), фильтр по группе и поиск по названию/адресу |
| **Пресеты раскладок** | Сохраните нужный набор камер и раскладку, чтобы открывать его одним кликом |
| **Миниатюры и снимки** | Кадры-превью в списке камер обновляются автоматически, кнопка `⤓` сохраняет снимок |
| **Пользователи и роли** | Администратор / наблюдатель, смена паролей, при первом запуске — мастер создания админа |
| **Диагностика** | Статус каждого потока (live/error), FPS, разрешение, битрейт, лог ffmpeg с «замазанными» паролями |
| **Экономия ресурсов** | Поток запускается, когда камера попала на экран, и гаснет через 25 секунд без зрителей; автоперезапуск с backoff |
| **Демо-режим** | Две синтетические камеры в комплекте — интерфейс можно посмотреть до подключения железа |

Архив, детекция движения и уведомления сознательно **не реализованы** на этом этапе:
архив уже есть на регистраторе, а эти функции — следующий шаг (см. «Дальнейшее развитие»).

## Быстрый старт

Требуется **Node.js 22.5+** (используется встроенный `node:sqlite`) и ffmpeg.

```bash
npm install          # зависимости + статические сборки ffmpeg/ffprobe
npm start            # http://localhost:8080
```

При первом открытии приложение попросит создать администратора (пароль от 8 символов).
Демо-камеры уже включены в `config/cameras.json`, поэтому картинка появится сразу.

Если в системе уже есть свежий ffmpeg, он будет использован вместо npm-сборки
(порядок: `FFMPEG_PATH` → `PATH` → npm-пакет).

### Полезные переменные окружения

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `PORT` | `8080` | Порт веб-интерфейса |
| `HOST` | `0.0.0.0` | Интерфейс прослушивания |
| `DATA_DIR` | `./data` | БД пользователей, HLS-сегменты, снимки |
| `CAMERAS_CONFIG` | `./config/cameras.json` | Путь к файлу с камерами |

## Подключение камер Amatek

Все настройки — в `config/cameras.json`. Файл перечитывается на лету: правьте и сохраняйте,
перезапуск не нужен. Образец со всеми вариантами — `config/cameras.example.json`.

```json
{
  "server": { "port": 8080, "title": "Видеонаблюдение Amatek" },
  "groups": ["Периметр", "Вход"],
  "cameras": [
    {
      "id": "nvr-1",
      "name": "Периметр — вход",
      "group": "Периметр",
      "vendor": "amatek-nvr",
      "host": "192.168.1.88",
      "port": 554,
      "username": "admin",
      "password": "ваш_пароль",
      "channel": 1,
      "stream": 0
    }
  ]
}
```

### Шаблоны RTSP-ссылок (`vendor`)

| `vendor` | Формат ссылки | Пример |
|---|---|---|
| `amatek-nvr` | `rtsp://user:pass@IP:554/<канал-1><поток>` | `rtsp://admin:12345@192.168.1.88:554/00` — канал 1, основной поток |
| `amatek-xmeye` | `rtsp://IP:554/user=…&password=…&channel=N&stream=S.sdp` | `rtsp://192.168.1.10:554/user=admin&password=12345&channel=1&stream=0.sdp` |
| `generic` | `rtsp://user:pass@IP:554/Streaming/Channels/<канал><поток>` | типовой ONVIF: канал 1, основной → `/Streaming/Channels/10` |

Нумерация: у NVR F-серии и XMEye каналы в ссылке начинаются с **1** (в шаблоне F-серии
это автоматически превращается в `channel-1`), `stream=0` — основной поток, `stream=1` — дополнительный.

Если у устройства нестандартный путь, задайте ссылку целиком — доступны подстановки
`{host}`, `{port}`, `{user}`, `{password}`, `{userAuth}`, `{channel}`, `{channelIndex}`, `{stream}`:

```json
{ "id": "custom", "name": "Своя ссылка", "rtsp": "rtsp://{userAuth}{host}:{port}/live/ch{channel}" }
```

### Поля камеры

| Поле | По умолчанию | Описание |
|---|---|---|
| `id` | — | Уникальный идентификатор (латиница, цифры, `-`) |
| `name`, `group` | `id`, «Без группы» | Подписи в интерфейсе |
| `vendor` | `generic` | Один из шаблонов выше |
| `host`, `port` | —, `554` | Адрес устройства |
| `username`, `password` | — | Учётные данные; в браузер не передаются |
| `channel`, `stream` | `1`, `0` | Канал и поток по умолчанию |
| `rtsp` | — | Готовая ссылка (перекрывает шаблон) |
| `transport` | `tcp` | `udp` иногда снижает задержку, но чаще рвётся |
| `maxWidth` | без ограничения | Даунскейл перед кодированием (например `1280`) |
| `fps` | как у источника | Ограничение частоты кадров |
| `enabled` | `true` | Отключённые камеры видны в списке, но не стримятся |
| `warm` | `false` | Держать поток запущенным постоянно (быстрый старт, больше CPU) |

## Как это устроено

- **Сервер** — Node.js + Express. Учётные записи в SQLite (`node:sqlite`), пароли — `scrypt`,
  сессии в HttpOnly-cookie на 12 часов.
- **Трансляция** — на каждую камеру и качество поднимается отдельный процесс ffmpeg:
  RTSP → H.264 → HLS (сегменты по 2 с, 6 сегментов в плейлисте, `zerolatency`).
  Браузер играет HLS через hls.js, поэтому работает везде, включая Safari и мобильные.
- **Ресурсы** — плеер просит сервер запустить поток при открытии плитки и сообщает об уходе;
  без зрителей поток гаснет через 25 с. При ошибке — перезапуск с нарастающей паузой (до 30 с).
- **Безопасность** — RTSP-ссылки с паролями не покидают сервер, в клиентских ответах и в логах
  учётные данные замаскированы (`admin:***@`).

## Типичные проблемы

| Симптом | Причина и решение |
|---|---|
| «Connection refused» | Неверный IP/порт, устройство выключено, RTSP отключён в настройках NVR |
| «401 Unauthorized» | Неверный логин/пароль или в пароле есть `#` (Amatek такое не поддерживает) |
| Поток есть, картинки нет | Камера отдаёт H.265, а браузер — нет: ffmpeg перекодирует в H.264 автоматически, проверьте лог в диагностике |
| Рваная картинка, задержка 3–5 с | Это норма для HLS; уменьшите `segmentSeconds` до 1 или используйте дополнительный поток |
| Высокая нагрузка CPU | Смотрите «дополнительный» поток в сетке (`sub`), задайте `maxWidth`/`fps` |

## Дальнейшее развитие

Основа готова, и следующие шаги ложатся на неё без переделки архитектуры:

1. **Архив** — воспроизведение записей с NVR: поиск по времени и экспорт клипа (RTSP playback
   у Amatek отдаёт запись по тому же каналу).
2. **Уведомления** — детекция движения по снимкам (раз в N интервалов сравниваем кадры) плюс
   отправка в Telegram/на почту, push в браузер.
3. **Автообнаружение** — сканирование подсети по ONVIF, подстановка найденных камер в конфиг.
4. **Мобильная вёрстка** — сейчас интерфейс адаптивен, но отдельный режим «телефон» с одной
   камерой и быстрым переключением будет удобнее.
